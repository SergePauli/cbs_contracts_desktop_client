# Что нового

## Исправления

- Диалог сотрудника переведён на статический XAML с привязками данных: поля, шаблоны подсказок, список контактов и кнопки. Убрано ручное пересоздание элементов контактов.
- При добавлении сотрудника из Контрактов проверяется актуальность ContractWorkflow; контрагент фиксируется в состоянии открываемого диалога.
- Автокомплит должности использует поиск «Начинается с».
- При закрытии диалога отменяются незавершённые запросы подсказок. Ошибки загрузки подсказок записываются в diagnostics.log.
- Ошибки добавления сотрудника из Контрактов записываются в diagnostics.log с местом, этапом, параметрами вызова и стеком исключения.
- Разделены выбор строки и применение данных ContractWorkflow. После сохранения контракта устранены повторный вызов загрузки деталей и обработка замены строки как нового выбора; представление и аудит обновляются по событию применения данных.
- В таблице «Этапы» устранено повторное обновление DetailView после закрытия сохранённого контракта. Уведомление об успешном сохранении показывается при сохранении, а не после закрытия диалога.
- Общий сценарий сохранения, уведомления, закрытия и обновления вынесен в ContractWorkflowHostViewBase для Контрактов, Этапов и Ревизий, включая редакторы этапа ОЗИ/финансов. В Ревизиях после сохранения контракта обновляется исходная ревизия.
- Email-контакты сотрудника перед сохранением приводятся к нижнему регистру; удаляются пробелы по краям. Нормализация применяется при создании и редактировании сотрудника.
- При копировании информации о контракте перед номером документа добавляется «№». Если внешний номер пустой, используется внутренний номер контракта (name, с символами «/»).
- В редакторе контракта массовое сворачивание/разворачивание применяется ко всем этапам, включая строки вне экрана. Поля этапа перенесены в статический XAML; редакторы подготавливаются перед показом узлов и сохраняются, изменение полей больше не пересоздаёт всё дерево.
- Убрано создание редактора этапа из Loaded строки дерева: содержимое подготавливается до подключения узлов, чтобы не менять загружаемую строку повторно. Начало и завершение подготовки редактора записываются в diagnostics.log с ID контракта и этапа.
- Открытие редакторов и окон информации в Контрактах, Этапах и Ревизиях проходит через общий метод ContractWorkflowHostViewBase. Ошибки открытия записываются в лог и выводятся в строке ошибки host; добавлена трассировка входов и открытых окон для диагностики конфликта ContentDialog.
- Дерево этапов переведено на явные TreeViewNode: дочерние узлы подключаются до раскрытия, XAML-шаблон отображает только содержимое. Убраны конкурирующие привязки ItemsSource/IsExpanded у TreeViewItem; скрытая ветка поставки исключается из коллекции дочерних узлов.
- Исправлено владение редактором этапа при повторном использовании контейнеров TreeView: сохранённый элемент отсоединяется от прежнего контейнера перед подключением к новому. При выгрузке строки ссылка освобождается; поля редактора не пересоздаются.
