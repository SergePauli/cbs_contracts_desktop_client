# Экспорт таблиц в Excel

Кнопка доступна пользователям с ролью `excel` в списке ролей через запятую.
Она подключена в `ComplexHostViewBase` и `ReferenceHostView`: функциональные таблицы и справочники используют один движок.

## Состояние и загрузка

- `TablePageStore.CreateExportRequest()` проверяет роль и снимает копию определения таблицы с видимыми столбцами в текущем порядке.
- `LazyDataViewState.CreateQuerySnapshot()` использует существующий `DataQueryStateBuilder`, фиксирует сериализованные фильтры и сортировку и добавляет `id asc` как вторичную сортировку, если сортировки по ID ещё нет.
- `TableExportControl` фиксирует тему, плотность, ширины столбцов и настройку отображения копеек; выбирает файл и показывает прогресс/отмену.
- `TableExcelExportService` вызывает один `api/count`, затем `api/index` с `offset` и `limit` до 1000. Экспорт не использует виртуализированную коллекцию экранных строк и не меняет её фильтры или содержимое.
- Запросы остаются в контексте вызывающего приложения; запись пачек и завершение XLSX выполняются в фоне. Это сохраняет существующую доставку диагностических событий API.
- Пустая выборка создаёт файл с заголовками. Неожиданная пустая страница до достижения count прерывает экспорт с ошибкой.
- Настройки зафиксированы, но серверного снимка данных нет: изменение записей другими пользователями во время offset-пагинации может изменить состав/порядок выгрузки.

## Значения и оформление

`TableCellPresentationBuilder` используется рендерером таблицы и Excel. Новые настройки типов столбцов не вводятся: используются `DisplayField`, `ApiField`, `FieldKey`, `Filter.Mode`, `BodyMode`, `BodyTemplateKey`, исходные типы значений и существующие правила составных ячеек.

Общее описание содержит значение, отображаемый текст, числовой формат, ARGB-цвета текста/фона, жирность, размер шрифта и выравнивание. XAML-ресурсы разрешаются на стороне представления через `TablePresentationResources`. Цвета статусов также используются диалогами выбора статуса.

- Даты записываются как числовые значения Excel с форматом даты/времени, с тем же переводом в локальное время, что в таблице.
- Суммы сохраняют исходную точность, формат отображения учитывает режим копеек. Обычные числовые значения остаются числовыми.
- Числа длиннее 15 десятичных цифр записываются текстом, чтобы Excel не изменил точное значение.
- Булевы столбцы записываются текстом из общего представления ячейки, как в таблице приложения: `✓` для true, пустая строка для false, `?` для null и `⌛` для неопределённого «БЗ». Вычисляемый столбец «СЗИ» также сохраняет своё отображение. Символы не зависят от локали Excel; цвета и выравнивание сохраняются.
- Статусы, ДСП, реестр, длительность с обозначением дней и прочие составные значения используют существующее представление.
- Сохраняются смысловые цвета, подсветка сроков, формат сумм, выравнивание, ширины и сетка. Выделение строк/ячеек, наведение, нажатие и фокус не входят в экспорт.
- Пользовательские строки записываются как inline string, а не как формулы.

## Файл и ошибки

`ExcelTableWriter` использует Open XML SDK и последовательную запись строк через `OpenXmlWriter`. В памяти приложения не строится DOM всего листа. Заголовки закреплены, включён автофильтр Excel.

Готовый файл заменяет целевой только после успешного закрытия книги. При отмене/ошибке временный файл удаляется. Отмена доступна кнопкой; уход с экрана также отменяет операцию.

Ошибки преобразования содержат номер строки Excel и столбец. Ограничения одного листа: 1 048 575 строк данных плюс заголовок; длина текста ячейки — до 32 767 символов. Превышение приводит к явной ошибке, без обрезания данных.
